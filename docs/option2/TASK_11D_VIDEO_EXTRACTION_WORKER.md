## 2. Core Integrity Checks and Specification Alignment

### 2.1 Strict Pilot Codec Policy (H.264 / H.265 in MP4 / MOV)
- **Approved Pilot Spec:** Only H.264 (`h264`) and H.265 / HEVC (`hevc`) within MP4 (`mp4`, `m4v`) or QuickTime MOV (`mov`, `quicktime`) containers are accepted.
- **Enforcement:** `lib/viewing-assessment/video/media-inspector.ts` explicitly restricts `ALLOWED_VIDEO_CODECS = ["h264", "hevc"]` and `ALLOWED_CONTAINER_FORMATS = ["mp4", "mov", "quicktime", "m4v"]`.
- **Rejection:** Legacy or unsupported formats (MPEG-4 Part 2, VP9, AVI, WebM) are rejected immediately prior to frame extraction with audited failure code `UNSUPPORTED_CODEC`.

### 2.2 Genuine Source Presentation Timestamp (PTS) Integrity & VFR Support
- **Requirement:** `source_time_ms` must be derived from actual source stream presentation timestamps, not inferred from frame sequence numbers or nominal framerate (which fail on variable-frame-rate / VFR mobile footage).
- **Implementation:** Added `probeStreamPresentationTimestamps(filePath)` to `media-inspector.ts` which executes:
  ```bash
  ffprobe -v error -select_streams v:0 -show_entries packet=pts_time -of csv=p=0 <filePath>
  ```
- **Sampling:** `selectExtractionTimestamps(genuinePts, durationSec)` samples candidate timestamps strictly from verified stream presentation timestamps.
- **Verification:** Verified in synthetic VFR integration tests comparing stored `source_time_ms` against independently probed PTS values with millisecond precision.

### 2.3 Contact Sheet & Derivative Labeling (Preserving Pristine Original PNGs)
- **Requirement:** Contact sheets must display a legible frame identifier and `mm:ss` timestamp on each tile, labeled as derivatives. The original full-resolution extracted PNGs must remain 100% unenhanced, unmodified, and free of overlaid text.
- **Implementation:**
  - Original frames extracted via `ffmpeg -ss <t> -i <in> -vframes 1 -an -c:v png -y <outputPngPath>`: lossless PNG with audio stripped.
  - Thumbnails downscaled to 320px JPEG derivatives.
  - Contact sheet generated by creating temporary annotated tile derivatives using FFmpeg `drawtext` with clean font fallback and escaped colons (`F00  00:00 [DERIVATIVE]`), which are then tiled via `tile=...` and saved as `contact_sheet.jpg`.
  - Full-resolution PNG files on disk and in private storage remain byte-for-byte pristine.

### 2.4 Cryptographic Provenance & Byte Verification
- **Original Media:** SHA-256 hash calculated over the downloaded original video bytes and matched against stored database records.
- **Extracted Frames:** SHA-256 hash computed over the actual file bytes of each extracted full-resolution PNG.
- **Verification:** Integrity tests re-read the PNG bytes from storage, recompute their SHA-256 hashes, and verify 100% equality with the database `sha256` column.

### 2.5 Worker Concurrency & Lease Fencing
- **Requirement:** Stale workers whose lease has expired or whose job was reclaimed by another worker must be prevented from publishing output, transitioning status to `ready_for_review`, or overwriting database/storage records.
- **Implementation:**
  - `completeVideoJob(jobId, { workerId, ... })` and `markJobFailed(jobId, failureCode, workerId)` in `video-jobs-repository.ts` enforce conditional atomic updates:
    ```sql
    UPDATE brik_by_brik_engine.video_jobs
    SET state = 'ready_for_review', ...
    WHERE id = $1
      AND worker_id = $7
      AND (lease_until IS NULL OR lease_until > NOW())
    RETURNING id;
    ```
  - If the lease expired and another worker claimed the job, the stale worker's completion query affects 0 rows, throwing a lease lost error and halting artifact publication.

### 2.6 Storage Integrity & Reviewed Evidence Protection
- **Requirement:** Reviewed evidence (`is_reviewed_evidence = TRUE`) cannot be overwritten or deleted by subsequent extraction runs or worker re-executions.
- **Implementation:**
  - `insertVideoFrames` uses `ON CONFLICT (job_id, frame_index) DO UPDATE ... WHERE video_frames.is_reviewed_evidence = FALSE`.
  - Any frame already accepted as reviewed evidence is completely protected against overwrite.
  - Storage paths remain private and scoped: `video-evidence/{dealId}/{jobId}/...`.

### 2.7 Failure Handling & Temp File Cleanup
- **Rejections:** Corrupt media (`CORRUPT_MEDIA`), unsupported codecs (`UNSUPPORTED_CODEC`), duration $> 300$s (`DURATION_EXCEEDED`), resolution $> 1080$p equivalent (`RESOLUTION_EXCEEDED`), and retry exhaustion (3 attempts) are audited and handled cleanly.
- **Guaranteed Cleanup:** Temporary processing directories (`os.tmpdir()/brik-video-worker-*`) are cleaned up in `finally` blocks, leaving zero orphaned files on disk.

### 2.8 Retention & Paid AI Invariance
- Original evidence retained under `RETAIN_PENDING_OWNER_POLICY`.
- Temporary scratch cleanup remains completely separate from evidence retention.
- Zero paid AI or vision APIs invoked; 100% deterministic local FFmpeg / Node / Postgres.

### 2.9 Financial & Investor Shield Invariance
- Worker operations modify only `video_jobs` and `video_frames`.
- Parent `saved_deals` figures, True MAO, approved costs, and Investor Shield decisions remain completely untouched and invariant.
